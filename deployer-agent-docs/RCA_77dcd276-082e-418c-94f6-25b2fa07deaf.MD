# RCA — run 77dcd276-082e-418c-94f6-25b2fa07deaf (alert-dedupe-mongo)

## Summary
Initial deploy failed at the **pull_source / prepare-build-context** step. The deployer reads the env files declared in `config.yaml` (`env_paths: backend/.env`, `frontend/.env`) out of the pulled source. `backend/.env` does not exist, so build-context preparation aborted before any image build, mongo migration, or secret capture ran.

## Exact error
```
build: prepare build context: read envs: read env file backend/.env:
open /tmp/agent-env-...-/app/backend/.env: no such file or directory (PathError)
```
Step timeline (get_step_status): `wakeup_environment` success → `build` **failed** immediately (0s) with the above → all later steps marked "not run: an earlier deploy step failed".

## Root cause
The app is a `fastapi_react_mongo_shadcn` (farm) template. The farm build contract requires `backend/.env` to be present in the source — it is where the deployer reads the backend's environment (e.g. `MONGO_URL`, `DB_NAME`) to carry it into the deployment. The file is missing from the preview source tree, so pull_source cannot assemble the build context.

This is NOT a manifest fault: `config.yaml` correctly lists `backend/.env`. Removing it from `env_paths` would be wrong — it would strip the backend's env configuration from the deploy. The correct fix is to restore the missing file in source.

## Verification status
Diagnosed, NOT reproduced. The eph sandbox could not be spawned — `spawn_eph_pod` returned `eph_source_access_failed` (transient) on 4 attempts, consistent with the source archive being unavailable after a pull_source failure. Diagnosis rests on the authoritative step error above.

## Fix (E1 — source environment)
Create `backend/.env` in the app source with the backend's required environment variables, at minimum the Mongo config the app reads, e.g.:
```
MONGO_URL="mongodb://localhost:27017"
DB_NAME="alert_dedupe"
```
(Match the variable names the backend actually reads in `backend/server.py` / settings. Production `MONGO_URL`/`DB_NAME` are re-pointed by the deployer's mongo + secrets steps; the file just needs to exist and carry the keys the backend expects.)

After creating `backend/.env`, re-trigger the deploy. Do not edit the deployment manifests — they are correct.
