# RCA — build_image failure (run b0ae5b64-7571-4eff-8969-b4769c574df0)

**Deployment:** alert-dedupe-mongo
**Template:** fastapi_react_mongo_shadcn_base_image (farm), arm64, tier_0
**Failed step:** build_image (Cloud/CodeBuild)
**Verdict:** SOURCE-level fault — a repo-root `.dockerignore` incompatible with the farm template build. Fix belongs in the user's source (E1 applies it). NOT a manifest fix, NOT infra, NOT a missing file.

## Symptom
Build failed at the backend-build stage. Error (repeated for every COPY from context):
```
#13 [backend-build 7/13] COPY pip-cache/pip-bin /tmp/pip-bin
#13 ERROR: failed to calculate checksum of ref ...: "/pip-cache/pip-bin": not found
#24 [backend-build 5/13] COPY backend/ /app/backend/      -> "/backend": not found
#18 [frontend-build 6/14] COPY frontend/ /app/            -> "/frontend": not found
#21 [final-base 6/13]  COPY nginx.conf /etc/nginx/nginx.conf -> "/nginx.conf": not found
#23 [final-base 4/13]  COPY entrypoint.sh /entrypoint.sh  -> "/entrypoint.sh": not found
#22 [backend-build 6/13] COPY pip-cache/pip-wheels /tmp/pip-cache -> "/pip-cache/pip-wheels": not found
```
The error excerpt the trigger surfaced only showed the first (`pip-cache/pip-bin`); the full build log shows **every** template `COPY` source is missing from the context.

## Root cause
The repo root ships a custom `.dockerignore`:
```
*
!requirements.txt
!config.py
!notifier/
!dashboard/
dashboard/web/
!kb/
!config/
!data/Roster_*.csv
!docker/
!scripts/check_slack.py
**/__pycache__
```
The leading `*` excludes the entire context, and the re-include whitelist lists only the user's own `docker-compose` layout (`config.py`, `notifier/`, `dashboard/`, `kb/`, `config/`, `docker/`, …). It does **NOT** whitelist the paths the Emergent farm template's `Dockerfile.cloudbuild` copies:
- `backend/`  (COPY backend/ /app/backend/)
- `frontend/` (COPY frontend/ /app/)
- `nginx.conf`
- `entrypoint.sh`
- `pip-cache/pip-wheels`, `pip-cache/pip-bin`

So BuildKit built a context of only the whitelisted files (`load build context: transferring context: 847.95kB`) and the template's COPYs for everything else failed with `not found`.

This `.dockerignore` was authored for the user's own Dockerfile/compose build, not the platform template — the two are incompatible.

## Evidence (verified in eph sandbox on this run's pulled source)
- `/app/scratch` contains the full source: `backend/` (server.py, requirements.txt, .env), `frontend/` (.env, build/, package.json), `nginx.conf`, `entrypoint.sh`, `pip-cache/pip-bin`, `pip-cache/pip-wheels`. The files the build called "not found" are all present on disk.
- `cat /app/scratch/.dockerignore` matches the content above — `*` + narrow whitelist omitting backend/frontend/nginx.conf/entrypoint.sh/pip-cache.
- Build raw log: `#4 load .dockerignore transferring context: 490B` (the customer file is in effect) and `#8 load build context: 847.95kB` (only the whitelisted subset shipped).
- Verification is static (source present + ignore rules exclude the COPY sources); a real rebuild was not run in-pod (no buildx in the sandbox). The causation is unambiguous from the two facts together.

Note: this is a *different* failure from the prior run (77dcd276), which failed earlier at prepare-build-context because `backend/.env` didn't exist. That `.env` now exists, so prepare passed and the build advanced to the COPY stage where the `.dockerignore` bites.

## Fix (apply in the user's source, then redeploy)
**Option A (recommended, simplest):** delete the repo-root `.dockerignore`. The platform already strips `node_modules`/`.git` at prepare-build-context via `config.yaml` `exclude_dirs`, so a custom ignore file is not needed for the template build.

**Option B (keep an ignore file):** replace it with a template-compatible version that does NOT exclude the template's COPY inputs. Minimal safe form:
```
# only trim obvious noise; never exclude backend/, frontend/, nginx.conf,
# entrypoint.sh, pip-cache/, or requirements.txt — the farm template COPYs them.
**/__pycache__
**/*.pyc
.git
node_modules
```
Do NOT use a `*` + whitelist scheme unless the whitelist explicitly re-includes `backend/`, `frontend/`, `nginx.conf`, `entrypoint.sh`, and `pip-cache/`.

After the source fix, re-trigger the deploy. (Secrets/Mongo provisioning noted in the request still apply once the build passes — MONGO_URL/DB_NAME are localhost placeholders in backend/.env and should be replaced by the dedicated Atlas DB; that is unaffected by this build fix.)
